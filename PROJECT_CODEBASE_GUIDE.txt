1. ARCHITECTURE OVERVIEW & EXECUTIVE SUMMARY
================================================================================

1.1 ARCHITECTURAL PRINCIPLE: 100% CLIENT-SIDE PRIVACY & ZERO LATENCY
Ad Creative Intelligence is an advanced creative analytics web application built
on React 18, TypeScript, and Vite. 

A fundamental design decision of this system is that it operates 100% CLIENT-SIDE
directly in the user's browser.
- No remote backend server (FastAPI/Node/Django) is required.
- No database (PostgreSQL/MongoDB) is needed.
- No creative images or sensitive advertising performance metrics (spend, revenue)
  are ever transmitted over external networks or stored in third-party clouds.
- Image decoding and visual feature extraction are performed locally via the
  HTML5 Canvas 2D Context API.
- CSV parsing is performed locally via PapaParse with client-side chunking.
- Statistical analysis (Welch's t-test, two-proportion z-tests, Wald 95%
  confidence intervals) is executed client-side in sub-millisecond time.

1.2 THE "150 IMAGES VS. 24 RESULTS" CLARIFICATION
Judges may ask: "Why did an upload of 150 creative images generate only 24 rows?"
The architecture makes a clear, rigorous distinction between two data outputs:

- OUTPUT A: CREATIVE-LEVEL ANALYSIS (150 ROWS)
  Every single uploaded creative image asset is processed, extracted, and matched
  against the CSV. The Image-Level Export ("Export Creatives CSV") contains exactly
  150 rows, documenting dimensions, dominant color, contrast, brightness,
  saturation, complexity, impressions, clicks, conversions, spend, CTR, CVR, CPA,
  and ROAS for every asset.

- OUTPUT B: AGGREGATE STATISTICAL RANKINGS (24 ROWS)
  Findings represent statistical hypotheses comparing contrasting cohorts of
  creatives (e.g. High Contrast vs. Low Contrast, Vibrant vs. Muted, Cool vs. Warm)
  evaluated across 4 metrics (CTR, CVR, CPA, ROAS). 
  6 binary attribute pairs multiplied by up to 4 applicable metrics produces
  exactly 24 statistical findings.

Both outputs are accessible, auditable, and downloadable directly from the UI.

  Important Functions:
    calculateCtr(clicks, impressions)       - Click-Through Rate = clicks / impressions.

FEATURE: K. Color Saturation and Brightness Calculations
FILE: src/services/analysis/featureExtraction.ts
FUNCTION: extractImageFeatures()
LINE: 125-128, 136-140, 169-178
CALLED FROM: featureExtraction.ts:54
INPUT: RGB pixel values
PROCESS:
1. Brightness: Perceptual luminance via ITU-R Rec. 601: luma = 0.299*R + 0.587*G + 0.114*B.
   Average luma >= 145 -> 'High Brightness', else 'Muted Brightness'.
2. Contrast: Population standard deviation of luminance across pixels:
   variance = sumLumaSq/N - meanLuma^2; contrast = sqrt(variance).
   Contrast >= 30 -> 'High Contrast', else 'Low Contrast'.
3. Saturation: HSV saturation = (max(R,G,B) - min(R,G,B)) / max(R,G,B) * 255.
   Average saturation >= 90 -> 'Vibrant Saturation', else 'Muted Saturation'.
OUTPUT: brightnessVal, contrastVal, saturationVal and categorical labels.
DEPENDENCIES: Rec. 601 perceptual color formula.
DEMO TIP: Open featureExtraction.ts:172-175 to show the standard deviation contrast formula.

PROCESS:

FUNCTION: compareProportions
FILE: src/services/analysis/statisticalTests.ts:28-110
PURPOSE: Two-proportion z-test with 95% Wald confidence interval for binomial metrics (CTR, CVR).
PARAMETERS: groupA, groupB (counts, numerators, denominators), groupALabel?, groupBLabel?
RETURNS: ComparisonResult
PROCESSING STEPS:
1. Computes group rates p1 = numA / denA and p2 = numB / denB.
2. Checks underpowered guardrails (count < 5 or denominator <= 0).
3. Computes standard error se = sqrt( (p1*(1-p1)/nA) + (p2*(1-p2)/nB) ).
4. Computes 95% CI = [diff - 1.96*se, diff + 1.96*se].
5. Computes zScore = diff / se and pValue = 2 * (1 - normalCdf(|zScore|)).
CALLED FROM: src/services/analysis/evidenceClassifier.ts:201
ERRORS / EDGE CASES: If se is zero or sample size is inadequate, flags isUnderpowered = true and returns null CI.

--------------------------------------------------------------------------------
FUNCTION: compareMeans
FILE: src/services/analysis/statisticalTests.ts:116-181
PURPOSE: Welch's two-sample t-test with 95% CI for continuous metrics (CPA, ROAS, CPC).
PARAMETERS: valuesA (number[]), valuesB (number[]), groupALabel?, groupBLabel?
RETURNS: ComparisonResult
PROCESSING STEPS:
1. Computes sample means meanA and meanB.
2. Computes unbiased sample variances varA and varB.
3. Computes standard error se = sqrt( varA/nA + varB/nB ).
4. Computes 95% CI = [diff - 1.96*se, diff + 1.96*se].
5. Computes z-score and approximate p-value.
CALLED FROM: src/services/analysis/evidenceClassifier.ts:251
ERRORS / EDGE CASES: Requires at least 5 observations per group to calculate variance; otherwise flags underpowered.
